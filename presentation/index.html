Slide 02 — 現在の背景

対面サービスにおける順番待ちの日常的な課題

従来の受付体験における課題点と不透明さ

従来体験の課題

📌 受付付近から離れられない

発券後に待合エリアで待機を余儀なくされ、自由に行動できません。

⏳ 待ち時間・順番が不透明

目安時間（ETA）や前方の待ち人数が分からず不安が生じます。

📢 手動・口頭での呼出し

スタッフの呼び出し負担と聞き逃しリスクが生じます。

🏢 待合スペースの過密化

混雑した待合エリアは店舗イメージ低下に繋がります。

Wait Time Context (Japan)
多くの店舗やサロン、クリニックでは、お客様が受付で番号札を受け取り、待合エリアで待機し続ける必要があります。

問題は待ち時間そのものだけでなく、「あとどれくらいで呼ばれるか分からない」という不透明さにあります。

これによりお客様は受付を離れられず、スタッフも手動での呼び出しや問い合わせ対応に追われることになります。
Slide 03 — 直面する課題

順番待ちは「番号の発行」だけではない

運用現場における個別システムの分断と課題

現場運用の分断

📊 待ち時間が不透明

リアルタイムな予想待ち時間が提示されません。

🧩 業務システムが分断

受付、注文、在庫、決済が独立し二重入力が発生。

🔔 順番を逃すリスク

個人端末へ呼出し通知を送信する手段がない。

📉 運用データが集計不能

対応時間や離脱率を一元管理できていません。

Disjointed Systems Issue
単純に見れば、順番待ちシステムは番号を発行して呼び出すだけで足るように思えます。

しかし実際の店舗運用では、お客様の選択したメニュー、事前決済の有無、在庫状況、担当スタッフ、通知タイミングなど、多くの業務が絡み合っています。

これらが個別システムに分断されていると、店舗の円滑な運用やデータ分析が困難になります。

Slide 05 — 解決ソリューション

LINE-first Smart Queue Platform

LINE受付から店舗運用ダッシュボードまでを一本化

ソリューション概要
  • 店舗の固定QRコードをLINEアプリで読み取りスタート

お客様は店舗のQRを読み取り、LINE認証を経て、キューや商品・サービスを選択しデジタルチケットを受け取ります。

ステータスが更新されるとLINE Messaging APIから自動通知が届き、店舗側は役割ごとの専用ダッシュボードで効率的に運用できます。
Slide 06 — システム概要

LINE Smart Queue Assistant

導入申込みから店舗運用・顧客体験までを一貫サポート

Platform Scope

🏢 Business Onboarding

法人がWebから申請、プラン選択、デモ決済を行い、管理者の審査を受ける申込みフロー。

🌐 Multi-branch

複数拠点を独立管理。支店ごとに独自の固定QRコード、営業時間、スタッフを割り当て。

📦 Product Catalog

組織共通のサービス・商品カタログを1箇所で管理。実在庫（Stock）は支店別で管理。

🎫 Booking & Ticket

LINEから即時発券。混雑状況と平均サービス時間に基づき動的なETAをリアルタイム算出。

👨‍🍳 Staff Operation

スタッフ専用画面：呼出し・対応開始・完了、現地での残金会計、領収書発行を一画面処理。

💬 LINE Notification

発券完了・5人待ち・呼出し・対応完了・キャンセル等のステータス変化をLINEで自動送信。

LINE Smart Queue Assistantは、単なる発券画面にとどまりません。

法人の利用申込み、管理者による審査、オーナーによる組織設定、支店長によるキュー・在庫設定、 possessed、 Customerの予約とスタッフの対応完了まで、全運用サイクルをサポートする包括的なシステムです。
Slide 07 — 注目テクノロジー

アーキテクチャ & コア技術

信頼性の高いモダンSaaS技術スタックとLINE密連携

Tech Architecture

⚛️ Frontend Web UI

React + Vite: 爆速のページロードとスムーズな画面遷移。スマホからPCまで完全レスポンシブ対応。

🛡️ Backend API

Express + TypeScript: 堅牢なRESTful API設計、厳格なデータ型チェックとマルチテナント権限管理。

🗄️ Database

PostgreSQL: ACID一貫性を保持し、複数店舗・大量トランザクションを安全かつ確実に一元管理。

🟢 LINE Ecosystem

LIFF + LINE Login + Messaging API: LINE内アプリ直接起動、ワンタップ認証、自動通知の高度な統合。

技術構成において、本システムは最新かつ柔軟なスタックを採用しています。

フロントエンドはReactとViteを組み合わせ、圧倒的な読み込み速度とスムーズなUI操作を実現。バックエンドはExpressとTypeScriptで構築され、データ型と権限の安全性を確保しています。

データベースにはPostgreSQLを採用し、複数組織・支店・大量のチケットデータを確実に管理します。

最大の特長はLINEエコシステムとの深い連携であり、LIFFとLINE Loginによるアプリ内シームレス認証と、Messaging APIによる自動通知を実現しています。

Slide 10 — Business Onboarding

法人がWebから直接利用申請

初期パスワード入力なしの透明性の高い申請フォーム

Step 1 — Register
  • 法人名、屋号、登録番号、連絡先、住所を入力
  • 想定拠点数と月間顧客数から最適なプラン（Starter/Standard/Scale）を選択
  • デモ環境では Demo Payment を完了し審査待ちとして送信
  • 申請時点ではパスワード未設定でセキュリティを担保
Business Registration Form
法人の導入は公開ページの申込みフォームから始まります。

この段階ではパスワードを設定せず、法人情報、連絡先、想定規模、希望プランのみを入力します。

送信後、申請は管理者による審査ステータスとなります。
Slide 11 — Admin Approval

Platform Admin による申請審査

管理画面からの厳格な検証と承認フロー

Step 2 — Approval
  • 審査待ち申請一覧から法人情報およびデモ決済結果を確認
  • ワンクリックで Approve（承認）または Reject（却下）を実行
  • 承認時に Organization および招待状態の Owner アカウントを生成
  • 無許可の自動登録を防ぎ、プラットフォームの健全性を維持
Admin Application Detail
プラットフォーム管理者は届いた申請の細部を確認します。

承認を実行すると、組織データと招待状態のオーナーアカウントが自動生成されます。

未検証の利用を防ぎ、安全なプラットフォーム運用を担保する重要なステップです。
Slide 12 — Owner Activation

オーナーによるアカウント有効化

メールリンク経由で自らパスワードを安全設定

Step 3 — Activation
  • 承認完了後にオーナー宛てへ有効化メールを自動送信
  • 一回限りの安全なリンクからオーナー自身でパスワードを登録
  • Organization のステータスを正式に Active へ切り替え
  • 管理者が仮パスワードを発行しない安心のセキュリティ構造
Owner Activation
承認後、オーナーは専用メールリンクから自らパスワードを設定します。

管理者が初期パスワードを発行・共有しない設計により、セキュリティリスクを大幅に低減しています。
Slide 13 — Product / Service Catalog

カタログは Organization 単位で管理

商品定義の一元化と支店在庫の明確な分離

Catalog Management
  • 全支店で共有される商品・サービスマスタを統一登録
  • 自動採番コード（商品/サービス識別コード）による正確な管理
  • 標準価格、所要時間、事前決済（Require Prepayment）の設定
  • カタログ定義と各支店の物理在庫（Stock）を完全に分離
Owner Product Catalog
設計上の重要なポイントは、商品・サービスが組織レベルで管理される点です。

これにより、全支店で価格やサービス時間の定義を一貫して保つことができます。

一方で、各商品の実在庫（Stock）は各支店で個別に管理されます。
Slide 14 — Branch Management

1つの組織で複数支店を管理

多店舗展開に対応する柔軟なマルチブランチ構造

Branch Structure
  • オーナーが実店舗に対応する支店（Branch）を自在に登録
  • 各支店の責任者として Branch Manager を個別に招待
  • 支店ごとに独立した固定QRコードおよびアクセス権限を発行
  • 営業時間・定休日（Business Calendar）を拠点で個別に設定
Create Branch
オーナーは実店舗に対応する支店を作成し、支店長を招待できます。

各支店は独自の住所、営業時間、支店長、固定QRコードを持ち、多店舗展開を行う事業者に適した構造となっています。
Slide 15 — Branch Manager Workspace

支店ごとの独立した運用空間

担当店舗の現場データ・設定に限定された安全な管理画面

Manager Portal
  • Queue Management: 受付並び列の作成・編集・状態切り替え
  • Business Calendar: 臨時休業日や特別営業時間の登録
  • Stock Management: 自店舗の実在庫数の更新と補充設定
  • Staff Management: 現場スタッフの招待とシフト権限管理
  • Branch QR: 店舗設置用の専用固定QRコードの出力
Branch Manager Dashboard
支店長は割り当てられた店舗のみを管理します。

キュー、営業時間、在庫、スタッフ、QRコードを店舗の状況に合わせて柔軟に調整できます。

権限を支店内に限定することで、他店舗のデータ誤操作を防ぎます。
Slide 16 — Multi-Queue per Branch

1つの固定QR — 複数のキュー

QR貼り替え不要で柔軟なサービス分流を実現

Queue Architecture
  • 1つの店舗に「一般受付」「優先受付」「サービス専用」等を複数設置
  • キューごとに提供する商品・サービス（Queue Catalog）を指定
  • 店頭に掲示するQRコードは常に1つ固定で印刷・掲示の負担軽減
  • キューの追加・削除を行っても店頭のQRコードを変更する必要なし
Queue List
1つの支店内に複数のキュー（並び列）を作成できます。

たとえば「カット用」「カラー用」「優先受付」などを分けることが可能です。

店舗に掲示するQRコードは1つで済み、お客様が読み取り後に希望のキューを選択します。
Slide 17 — Queue Configuration

キューの柔軟な動作設定

現場の運用ルールを細部まで再現できる豊富なパラメータ

Queue Settings
  • ステータス制御: Open（受付中）/ Closed / Paused / Archived
  • 1日の上限受け入れ数（Capacity）制限で混雑を制御
  • チケット番号の識別前置詞（Ticket Prefix: A-, B-, P-等）設定
  • 動的ETA計算用の平均サービス時間（Average Service Time）定義
  • 不在時ルール（Absence Policy）および対応商品の個別割り当て
Create / Edit Queue
キューには実際の運用に即した詳細設定が備わっています。

受付状態、1日の受け入れ上限、チケット番号の接頭辞、平均対応時間、不在時の保留ルールなどを細かくチューニングできます。
Slide 18 — Branch Stock

支店ごとの在庫コントロール

Reserve ➔ Release ➔ Consume の自動在庫ライフサイクル

Stock Control
  • 有限在庫（Finite）と無制限在庫（Unlimited）の双方に対応
  • Reserve（確保）: 客のBooking完了時に即座に仮確保
  • Release（解放）: キャンセル・No-show時に自動で在庫復元
  • Consume（消費）: スタッフの接客完了時に実在庫を確定減算
  • 過剰予約（Overselling）を根本から防止する安全設計
Branch Stock Management
在庫は支店ごとに管理されます。同一商品であっても支店Aでは在庫あり、支店Bでは完売という状況に対応します。

予約時にReserve、キャンセル時にRelease、対応完了時にConsumeというライフサイクルで、過剰予約を防止します。
Slide 19 — Customer Journey with LINE

LINEからのシームレスな受付体験

離脱率ゼロを目指すシンプルなユーザーフロー

LINE Customer Flow
  • 店頭の固定QRコードを使い慣れたLINEカメラでスキャン
  • LINE Login による即時認証（会員登録・メール入力不要）
  • 希望の受付キューおよびカタログメニューを選択
  • 必要な連絡先を入力し、ワンタップでBooking（予約）完了
  • 発行されたデジタルチケットをスマホ上でリアルタイム確認
お客様視点では、店舗のQRコードをLINEで読み取ることから始まります。

メールアドレスやパスワードの新規登録は不要です。

LINE認証後、キューとメニューを選び、簡単な情報入力で即座に予約が完了します。
Slide 20 — Booking & Ticket

チケットは顧客体験の中心

必要な情報がすべて揃うデジタルステータス画面

Digital Ticket
  • Ticket Code & Order Number: 明確な受付番号と注文コード
  • People Ahead: リアルタイムでカウントダウンされる前方待ち人数
  • ETA (Estimated Time): 過去データに基づき算出される呼出し目安時間
  • Selected Items & Payment: 選択メニュー明細と支払済み/未払状況
予約完了後、お客様のスマホ上にデジタルチケットが表示されます。

番号だけでなく、前方に何人待っているか、あと何分で呼ばれるか（ETA）、注文内容、決済状況を一画面でリアルタイムに確認できます。

Slide 22 — Staff Operation

Staff Workspace
